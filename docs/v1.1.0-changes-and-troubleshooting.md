## 一、v1.1.0 改动内容

### 1. 版本号动态化（去掉硬编码）

**改动前**：`cmd/main` 硬编码 `ENV_PROBE_VERSION="1.0.2"`，`server.py` 默认值 `"1.0.2"`。每次 bump 版本要改两处，易遗漏导致前后端版本不一致。

**改动后**：
- `cmd/main` 从 manifest 动态读版本号，多路径兜底：
  ```bash
  APP_VER=""
  for mf in "/var/apps/${APP_NAME}/manifest" "${APP_DIR}/manifest" "${APP_DIR}/target/manifest"; do
      if [ -f "$mf" ]; then
          APP_VER="$(grep -E '^version' "$mf" 2>/dev/null | awk '{print $3}')"
          [ -n "$APP_VER" ] && break
      fi
  done
  [ -z "${APP_VER}" ] && APP_VER="1.0.0"
  ```
- `server.py`：`APP_VERSION = os.environ.get("ENV_PROBE_VERSION", "dev")`，无硬编码默认值。

### 2. 移动容器历史文案 → 动态判断

**改动前**：硬编码 `MOBILE_CONTAINER_HOST = "office.app.5ddd.com"`，靠匹配这个固定域名判断移动容器。此域名是早期猜测值，实测不可靠（飞牛移动 App 实际通过 FN Connect 子域名访问，每个用户/设备不同）。

**改动后**：移除固定域名，改为基于 **UA 特征 + FN Connect 域名（`*.fnos.net`）** 动态判断：
- 移动 App 内嵌 webview 的 UA 特征（fnos / fnconnect / 移动端）
- 或经 FN Connect 域名（非回环）访问
- 同时更新前端副标题、提示文案与 README 中历史表述

### 3. 连通性探测加局域网

**改动前**：只测本机 `127.0.0.1`（dsh/9Router/mihomo）+ 外网（GitHub/DeepSeek/FN Connect）。

**改动后**：新增局域网探测：
- 本机局域网 IP（LAN_IP）上的 dsh/9Router/mihomo
- 默认网关连通性（从 `/proc/net/route` 提取）
- 共 10 项探测：本机 3 + 局域网 3 + 网关 1 + 外网 3

## 二、排障记录（踩坑）

### 坑 1：`install-fpk` 不替换 app.tgz 里的 server.py

`sudo appcenter-cli install-fpk` 输出 "installed"，但**不会解压覆盖 app.tgz 里的 `server.py`**（保留了旧文件），只更新了 cmd/、manifest 等顶层内容。

**现象**：安装新 fpk 后，`/vol4/@appcenter/fn-netdiag/server.py` 仍是旧代码（对比 fpk 内文件确认）。

**解法**：手动从 fpk 解压 `server.py` 覆盖到 `/vol4/@appcenter/fn-netdiag/server.py`：
```bash
cd /tmp && tar xzf fn-netdiag.fpk && tar xzf app.tgz
sudo cp server.py /vol4/@appcenter/fn-netdiag/server.py
```

**教训**：任何 fpk 安装后，用 `grep` 对比实际文件与 fpk 内文件的关键特征，确认代码真的替换了，别信 "installed" 输出。

### 坑 2：`pkill -f "server.py"` 会误杀 SSH 会话

`sudo pkill -9 -f "server.py"` 会把**当前 SSH 命令也杀掉**（因为命令行里含 "server.py" 字样，`pkill -f` 按完整命令行匹配），导致 SSH 会话异常退出（exit 255）。

**解法**：不用 `pkill -f` 带路径字样的命令。改为：
```bash
# 用具体 PID 杀
PID=$(ss -tlnp | grep 28002 | grep -oE "pid=[0-9]+" | cut -d= -f2)
[ -n "$PID" ] && sudo kill -9 $PID
```
或 `pgrep -f "fn-netdiag/server.py"`（带应用路径，避免匹配到 ssh 命令）。

**教训**：`pkill -f` 匹配的是完整命令行，含目标字符串的**任何**进程（包括发起命令的 shell/ssh）都会被误杀。用具体 PID 或带应用特征路径的精确匹配。

### 坑 3：版本号 fallback 掩盖了"旧进程还在跑"

**现象**：改完 cmd/main 和 server.py，curl 首页仍显示旧版本（v1.0.2 或 v1.0.0）。

**根因**：旧 server.py 进程（用旧代码启动，已加载进内存）还占着 28002，新进程起不来（Address already in use）。改文件不影响已运行进程——Python 启动时已把代码读进内存。

**解法**：必须 kill 旧进程再启动，让新 server.py 生效。且要确认 manifest 版本已更新（否则 cmd/main 读到旧版本号）。

**教训**：改代码后，进程必须重启才生效。验证版本号要看「实际运行的进程」加载的代码，不是看文件。

### 坑 4：manifest 位置与 APP_DIR 的关系

`manifest` 在 `/var/apps/fn-netdiag/manifest`（fnOS 标准），而 `server.py` 在 `/vol4/@appcenter/fn-netdiag/`（`/var/apps/fn-netdiag/target` 软链指向）。`TRIM_APPDEST` 可能指向 `@appcenter`，导致 `cmd/main` 用 `${APP_DIR}/manifest` 找不到。

**解法**：cmd/main 读取 manifest 时把 `/var/apps/<app>/manifest` 放第一优先级（见上改动）。
